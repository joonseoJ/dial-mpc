# CSM이 RL보다 나을 수 있는 환경 찾기

2026-09-27. 목표는 "CSM이 일반적으로 우월하다"가 아니라, 조건과 가정을 붙여서라도
CSM이 RL을 이기는 환경이 **하나라도** 있는지 찾는 것이다. 스크립트는
`csm/niche/`, 로그는 `csm_runs/niche_*.log`.

## 판단 틀

CSM은 샘플링 플래너(DIAL)를 증류하므로 품질의 상한이 교사다. 그래서 CSM이 RL을
이기려면 다음 둘 중 하나가 필요하다.

1. **교사가 RL보다 강한 과제**: 같은 목적, 같은 정보에서 DIAL이 RL보다 잘하는 과제.
   거기서는 DIAL이 실시간이 아니므로(아래 표) CSM이 유일한 실시간 제어기가 되고,
   weight 합성은 RL이 어떤 weight에서도 못 푸는 과제에서 의미를 갖는다.
2. **RL이 구조적으로 못 보는 것**: 관측에 없는 정보를 CSM의 plan이 대신 들고 가는 경우.

weight family가 풍부하다는 것(여러 행의 혼합)만으로는 부족하다 — 아래 보행 스타일
결과처럼 조건부 RL이 혼합도 더 잘 푼다.

모든 RL 기준선은 같은 보상, 목적에 필요한 관측 전부(시간 인덱스 목적이면 gait 시계,
상자·지형이면 그 상태), 고정 지평선(넘어져서 비용을 끊는 편법 차단), 비유한 상태
방어(guard)를 갖는다.

## 결과

### 양성: 교사가 RL보다 강한 과제 (확실한 것 1개, 조건부 2개)

| 과제 | DIAL (교사) | PPO | DIAL 속도 |
|---|---|---|---|
| **H1 휴머노이드 상자 밀기** (30 kg 상자, 9개 행, 6초) | 2/2 선 채로 밂(상자 3.6–4.3 m 이동), 평균 보상 −0.07 | 5억 step: 3/3 넘어짐, 상자 0.04–0.08 m, −0.67 · **20억 step: 3/3 넘어짐, 상자 0.16 m, −0.69** | 제어 step당 약 0.85 s (실시간의 42배 느림) |
| **Go2 상자 오르기** (논문 plant, 20 ms 물리 step) | 두 번 실행해 3/3, 2/3 오름(성공 시 머리 목표 1 cm 이내; 실패한 한 번은 머리 0.70 m), −0.16 ~ −0.29 | 5억: 0/5 (상자 앞에서 넘어짐), −0.76 · **20억: 0/5 (앞다리만 걸침, 머리 0.67 m / 목표 0.87 m), −0.34** | 약 0.3 s (15배) |
| **Go2 징검다리** (12×2 돌, 약 25%가 0.3 m 구멍, 배치를 앎) | 0/16 낙상, 3.2 m 전진, 비용 6.97 | 5억 (배치 전체를 관측): **16/16 낙상**, 0.7 m · 커리큘럼(평지→10%→본 배치) 5억: 16/16 | 약 0.16 s (8배) |

붙는 가정:

- **A1 목적은 행 그대로 쓴다.** 보상 설계(생존 보너스, 종료, 모양 잡기)와 커리큘럼을
  RL에 주지 않는다. 표준 RL 관행을 쓰면 H1도 설 수 있을 것이다. "명세로 주어진 목적만
  쓴다"는 가정 아래서의 결과다.
- **A2 정확한 모델이 있다.** 교사와 RL 모두 같은 시뮬레이터를 쓴다.
- **A3 (상자 오르기만) 거친 plant.** 10 ms substep plant에서는 DIAL도 1/3만 오르고 PPO
  5억이 같은 부분 자세까지 간다. 20 ms plant에서는 PPO의 탐색이 물리를 발산시키고
  DIAL은 좋은 plan 근처만 굴려 안정적이다.
- **징검다리는 오염된 결과다.** 구멍 없는 평지 띠로만 학습해도 PPO가 걷지 못한다:
  1억 step은 1.6 m 가다 16/16 넘어지고, 5억 step은 학습이 발산해 출발 직후(8–20 step)
  16/16 넘어진다(평가 보상이 초기값 −1600보다 나빠진 −2300). 커리큘럼 판도 두 번째 단계에서
  발산했다. 이 plant(상자 24개 위의 접촉)는 탐색 중 비유한 상태가 잦고, 플래너는 그런
  롤아웃을 가장 나쁜 값으로 매겨 버리므로 영향을 받지 않는다. 즉 여기서 드러난 것은
  "발 디딤 계획"이 아니라 A3와 같은 "취약한 시뮬레이터" 조건이다.

**weight가 실제로 의미 있는 곳:** H1에서 행끼리 충돌한다(목표 속도로 걷기 vs 상자를
2 m에 세우기). uniform weight에서 DIAL은 상자를 2.3 m 지나쳐 밀고, 상자 행을 키우고
속도 행을 줄이면(`1,1,1,0.2,1,1,1,1,5`) 0.8–1.0 m로 줄어든다. 실행 중에 이 절충을
바꾸는 것이 CSM의 합성이 할 일이다.

### 양성(약함): 시계 없는 시간 인덱스 목적

걷기 gait 행은 시간으로 정해진 발 높이 스케줄이다. 관측에 시계가 없으면:

| boost2 (gait 비중 큼), DIAL 대비 비용 | 평균 |
|---|---|
| CSM (plan이 위상을 들고 감) | **1.10** |
| PPO, 시계 없음 | 2.71 |
| PPO, 과거 16 step 관측을 붙임 (시계 없음) | 2.52 |
| PPO + 시계 | 0.10 |

과거 관측 창으로는 위상을 되찾지 못한다. 조건은 "목적이 시간에 묶여 있는데 제어기에
시계를 줄 수 없다"이고, 재귀(RNN) 정책은 아직 비교하지 않았다. 실용적으로는 약한
조건이다 — 시계는 보통 줄 수 있다.

### 음성

- **보행 스타일 혼합(weight family가 풍부한 경우)**: 27개 weight(순수 4, 쌍 18, 삼중 4,
  4중 1) × 명령 3 × 무작위 초기 상태 4, 1500 step, 그 weight의 목적 비용으로 채점.
  조건부 PPO가 **81칸 전부에서** 비용이 낮다(붕괴는 양쪽 다 0)(순수 gait CSM 0.31–0.65 대 0.09–0.14,
  50:50 쌍 1.1–1.3 대 0.64–0.68, 4중 2.1 대 1.1). 서로 배타적인 모드를 한 망이 담는 것이
  조건부 RL에 크게 어렵지 않다.
- **표준 보행·외란 극복**: PPO + 시계가 DIAL보다 7–10배 싸다(`docs/research_direction_ko.md`).
- **실행 중 제약**: 제약 족으로 학습한 PPO가 CSM의 투영 합성보다 낫다(같은 문서 §3).

## 다음 실험 제안

**H1 상자 밀기에서 CSM.** 세 양성 환경 중 RL 실패가 가장 확실하고(20억 step에서도
넘어짐), 행이 이미 9개로 나뉘어 있고, weight가 결과를 실제로 바꾼다.

- 교사: DIAL(`unitree_h1_push_crate`), 수집 비용을 줄이려 annealing 4→2 수준이 되는지
  먼저 확인.
- 기저: 상자 중시 / 보행 중시 / 자세·에너지 중시 등 3–4개 weight.
- 사전 판정: 학생이 실시간(20 ms 이내)으로 6/6 선 채로 상자를 1.5 m 이상 밀고, weight를
  바꾸면 DIAL과 같은 방향으로 상자 최종 위치가 바뀐다. PPO(20억)는 이미 실패.
  학생이 2/6 넘게 넘어지면 중단.
- 비용 추정: 상태당 라벨 약 200만 env-step(4 수준 기준), 고정 시작점이라 상태 분포가
  좁아 수천–1만 상태 + DAgger 한 번이면 될 가능성 — 하루 규모.

두 번째 후보는 상자 오르기(고정 시작점이라 증류가 쉽지만, 20 ms plant 가정이 필요하고
행을 새로 나눠야 한다). 징검다리는 PPO 쪽 학습 불안정부터 풀어야 비교가 성립한다.

```bash
python -m csm.niche.h1_crate dial --seeds 2
python -m csm.niche.h1_crate dial --seeds 2 --omega 1,1,1,0.2,1,1,1,1,5
python -m csm.niche.h1_crate ppo --ppo-steps 2e9
python -m csm.niche.crate_rl dial --plant stock --seeds 3
python -m csm.niche.crate_rl ppo --plant stock --ppo-steps 2e9
python -m csm.terrain.gate --only oracle --episodes 16 --steps 300 --nsample 1024 --ms 8
python -m csm.niche.stones_rl --ppo-steps 5e8                  # [--curriculum] [--train-holes 0]
python -m csm.niche.walk_memory --k 16
python -m csm.niche.gait_cost --csm-policy csm_runs/gait-fit-d2/clouds-fit-20260916-090712/policy.pkl
```
